# Tlines 设计系统审计与最小改动方案

> **实施状态（2026-10-18）**：Phase A/B 已落地并完成本地验收，P0 与大部分 P1 已修复；Phase C 已完成核心组件收口与关键页面静态样式回收；Phase D 首轮 98 组合公开页矩阵、640px 重排、forced-colors、基础可访问性扫描和 axe-core WCAG A/AA 通过，0 failures / 0 axe violations；后台 16 个页面在 390/768/1440 无溢出，7 个代表页 axe 为 0 violations。仍报告 34 条内联链接小目标提示；CI 截图回归尚未完成。实施细节见 [CHANGELOG.md](./CHANGELOG.md)，证据见 [ACCEPTANCE_REPORT.md](./ACCEPTANCE_REPORT.md)。该版本已以镜像 `sha-bf43a00` 发布到生产（研究卡片等高、首页每家一条核心观察、研报标题右侧布局与 PDF 下载入口），回滚镜像 `sha-15c3bbf`、`sha-ffb99eb`、`sha-da6feb0` 保留在主机。

- 项目：Tlines（tlines.tech）
- 审计基线：`33c21be`
- 模式：审计记录（原 `MODE=AUDIT`；后续实现单独记录）
- 范围：公共站点主要页面 + 管理后台样本
- 目标：在不改变业务逻辑、品牌、路由、技术栈的前提下，建立可验证的 Primitive → Semantic → Component Token 体系，并先修风险最高的问题

## 0. 现有资产与保留项

Tlines 不是一张待重画的白纸，以下决策应原样保留：

- 中性墨色底 + 单一靛蓝行动色（`#5e6ad2` / 深色 `#7c8aff`）。
- 编辑衬线标题（`Source Serif 4` + 系统中文衬线）+ 系统无衬线正文 + 等宽数字。
- 冷静、低装饰、高信息密度的机构研究台气质，而不是改造成 Linear 的复制品。
- 现有 Light / Dark 双主题、CSS Variables、无 UI 框架依赖的自定义 CSS。
- 现有页面结构、路由、公开闸门、数据结构、后台权限和 API。
- 已有良好的 reduced-motion 处理、页面图片 alt、无横向溢出（除下述 320px 登录页）、非首页 h1 语义。

## 1. 审计方法与证据

静态盘点：

```text
globals.css 1,891 行；admin.css 516 行
237 个 font-size 声明，约 30 个不同字号
128 个 border-radius 声明，约 17 个不同值
71 个 media query，断点分散
120 个 CSS 十六进制字面量、33 个 rgba
243 处 TSX 内联 style；13 个 TSX 硬编码 hex
12 处 !important
4 个 :focus-visible 规则位置
```

浏览器实测（Chrome，Playwright；页面 `/zh`、`/zh/research`、研报详情、`/zh/news`、新闻详情、`/zh/methodology`、`/signin`；1440 / 390 / 320，Light / Dark）：

- 除 `/signin` 320px 外，页面无横向溢出。
- 公共页面图片 alt 检查未发现缺失。
- 首页 `h1` 数量为 0。
- 320px `/signin` 的 `scrollWidth = 354`，`clientWidth = 320`；溢出元素是 header 的 `.mobile-nav-toggle`（`right = 354`）。
- Dark 主按钮：白字 `rgb(255,255,255)` 置于 `rgb(124,138,255)`，实测约 **3.03:1**。
- Theme 选择写入 `localStorage.theme` 后刷新，`data-theme` 仍为 `null`，页面回到系统主题。
- Search 弹层与 MobileNav 用 Tab 可离开 `role="dialog"`，焦点没有闭环。
- `.minibtn`, `.chip`, `.page-head h1`, `.art-title`, `.site-footer` 等规则存在多次覆盖；例如 `.minibtn.p` 有 4 个基础定义，`.art-title` 出现 7 次。

### P2 — 品质与维护

- `globals.css` 中存在多轮覆盖：`.site-footer` 17 次、`.front-mast-stats` 12 次、`.topbar` 15 次、`.page-head h1` 4 次；新增样式容易靠 `!important` 或更靠后的位置取胜。
- 243 处内联 `style`，其中不少是静态字号、间距和颜色；需要把“动态值”与“一次性视觉值”区分，静态值回到 token/类。
- `/admin/design-system` 只列 14 个颜色变量，没有字号、间距、半径、状态和组件状态；它本身也使用内联尺寸，不能作为完整契约页。
- `global-error.tsx` 使用独立硬编码暗色 palette（`#0c0e13` 等），不随主题；错误页与站点主题割裂。
- `.iconbtn` 尺寸仅 `2px 6px`；一些后台链接/图标按钮小于 24px。
- 主题切换按钮缺少 `aria-pressed`/当前状态；`color-scheme`、`forced-colors` 未覆盖。
- 目前没有组件级视觉基线；`npm test` 覆盖 679 项业务/单元测试，但不能证明设计回归。
- 30 个字号、17 个半径、71 个断点：不是每个都错，但缺少“角色 → 值”的映射，导致页面靠局部记忆而不是系统约束。

## 3. 建议的设计主张

**冷静、可核验的机构研究台**：

1. 中性墨色表面承载信息，靛蓝只用于行动与链接；
2. 衬线只负责编辑标题，正文保持系统无衬线，数字用等宽；
3. 层级先靠布局、字号、留白，边框/阴影克制；
4. 信息密度高，但阅读行长、行高和数字对齐优先；
5. 状态永远有文字/形状，不只靠颜色。

这不是一次视觉翻新；Token 化后现有外观应基本不变，只修可读性与状态缺口。

## 4. Token 架构建议

### 4.1 Primitive（基础量，现存值优先）

| 组 | 建议 token | 现有依据 |
|---|---|---|
| Neutral | `neutral.0` … `neutral.12` | 由 `--paper`、`--bg`、`--panel*`、`--ink*`、`--border*` 归并 |
| Indigo | `indigo.2/9/10/11` | `--accent-wash`、`--accent`、`--accent-ink` |
| Status | `jade.*`, `ruby.*`, `amber.*`, `gold.*` | `--bull*`、`--bear*`、`--warn*`、`--accent-gold*` |
| Type | `type.sans/serif/mono` | 现有三套字体栈 |
| Space | `space.1..16` = 4…64 | 以 4px 节奏归并 5/7/9/11/13 等 |
| Radius | `radius.4/8/12/16/999` | 现有多数 6/7/8/10/11/12 归入 8/12 |
| Motion | `motion.fast/normal/slow` = 120/200/280ms | 现有过渡节奏 |
| Shadow | `shadow.raised/overlay` | `--shadow`、`--shadow-lift` |

### 4.2 Semantic（按职责，而不是按色相）

| 语义 | Light | Dark | 说明 |

| `surface.page` | `#fff` | `#0f1011` | 主面板 |
| `surface.subtle` | `#f1f2f4` | `#141516` | 次级面、备注底 |

| `text.secondary` | `#3c4149` | `#d0d6e0` | 正文 |

| `text.tertiary` | 建议 `#6b7280` 或更深 | 建议 `#7f858f` 或更亮 | 替代当前 `--faint` 的小号文字；必须 ≥4.5 |

- `button.danger.*`
- `chip.status.*`（最小高度 24，文字 11px）

- `card.surface/border/radius`
- `dialog.surface/overlay/focus`
- `table.header.bg/row.border/numeral`
- `nav.link/focus/current`

### 4.4 字号与间距

建议只保留角色，不保留 30 个数值：

```text
display  48–72 / 1.1    只用于品牌首页
h1       34–46 / 1.15   页面主标题
h2       28 / 1.25      区块
h3       20 / 1.35      子区
body     16.5 / 1.85    研报正文
body-sm  14 / 1.7       信息流正文、表格
meta     12 / 1.5       时间、来源、标签
micro    10–11 / 1.4    纯辅助、非必读
```

间距：4, 8, 12, 16, 20, 24, 32, 40, 48, 64。  
半径：4, 8, 12, 16, 9999（chip）。  
动效：120 / 200 / 280，全部遵守 `prefers-reduced-motion`。

## 5. 最小可验证改动顺序

### Phase A — 只加契约，不改外观

1. 新增 `tokens.css`（或 Token block），把现有 `--bg/--panel/--ink/...` **作为别名**指向新的 semantic token，保持所有旧类可用。
2. 记录当前 Light/Dark × 390/1440 的截图基线（已有 `baseline:redesign`，补公共页面）。
3. 在 `/admin/design-system` 增加新 token 分组和组件状态；不修改业务页面。

验收：`npm test && npm run typecheck && npm run build`；页面截图与基线无差异（除已声明视觉变更）。

### Phase B — 修 P0 / 最高风险 P1

按此顺序，一次只改一组：

1. `action.primary.fg`（Dark 主按钮）+ `focus.ring`；
2. `text.tertiary` 与状态色对比；
3. `/signin` 320 头部溢出；
4. Theme 首屏恢复 + `color-scheme`；
5. Search/MobileNav 焦点闭环；
6. 首页 h1；
7. 独立小链接/ chip 的 24px 目标。

每组验收：键盘路径、Light/Dark、390/1440、320（适用）、对比度实测、截图差异说明。

### Phase C — 组件契约与去重

- 固定 `.minibtn` 主/次/危险/disabled/loading 状态；
- 固定 `.chip` 状态色与最小尺寸；
- 把 `.art-title`、`.page-head h1`、`.minibtn.p`、`.site-footer` 的多轮覆盖收口到最后一组规则（先列冲突清单，再删除，不直接大清理）；
- 把静态内联样式回收到 token/类，保留动态值（宽度、百分比、用户状态）。

### Phase D — 页面迁移与回归

- 从首页、研报详情、新闻详情、方法论、登录页开始；
- 再处理后台密集数据页；
- 每页建立 Light/Dark × 390/1440 截图基线和键盘检查。

## 7. 待确认

1. Dark 主按钮选“深墨字 on 亮靛蓝”还是“压暗靛蓝 + 白字”？前者改动 token，后者改动品牌色阶。
2. `--faint` 的可读性修复会略微加深辅助文字；是否接受这是必要视觉变化？
3. 独立链接/ chip 采用 24px 最小目标，还是移动端统一 44px？后者更舒适但会增加行高。
4. 是否把当前保留的新闻右栏空白视为正式设计决策（本轮不填内容）。
5. 是否将 `project-profile.yaml` 和 `AGENTS_SNIPPET.md` 落入 Tlines 仓库，作为后续 agent 的长期约束。

## 8. 回滚与边界

- Phase A/B/D 只改 CSS/Token、极少量无业务语义的 JSX 和可访问性脚本；不改数据库、订单、权限、路由、发布闸门。
- 每组改动单独提交，保留旧 token 别名；页面级可通过恢复旧变量值回滚。
- 不引入 Tailwind、Radix Themes、组件库或新字体，除非后续明确批准。
